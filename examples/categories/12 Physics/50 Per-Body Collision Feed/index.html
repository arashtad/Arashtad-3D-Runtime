Per-Body Collision Feed

Route collisions from multiple bodies into separate GUI labels using Arashtad 3D Runtime and Havok physics.

What this demonstrates

A single helper receives collisions from three separate bodies and dispatches each one to its own card, so the reader can track per-body activity at a glance.

Routed Feed

Each box calls window.__feedCollision(name, event) with its own identifier. The helper updates the matching card's counter and last-collision line, so per-body state stays isolated.

Independent Counts

Because each card tracks its own counter, the reader can see which boxes bounce more or which one stops first. Different starting heights and restitution values make the streams visibly distinct.

Source

Each body funnels its collisions into a shared helper with its own name, which routes updates to the matching card. 

<arashtad-mesh
    id="greenbox"
    type="Box"
    size="1"
    position="new BABYLON.Vector3(-2.5, 8, 0)"
    material="green"
>
    <arashtad-physics
        type="BOX"
        mass="1"
        restitution="0.5"
        friction="0.5"
        startAsleep="false"
    >
        <arashtad-collision
            type="started"
            on-collide="
                window.__feedCollision('greenbox', event);
            "
        ></arashtad-collision>
    </arashtad-physics>
</arashtad-mesh>

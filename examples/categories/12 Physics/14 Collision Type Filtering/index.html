Collision Type Filtering

Filter collisions by started, continued, or finished types using Arashtad 3D Runtime and Havok physics.

Physics Collision Filtering
box1 · type="started" · box2 · type="started,continued"

What this demonstrates

Filter which collision phases reach the on-collide callback using the type attribute.

Type Attribute

type accepts a comma-separated list of phase names. box1 uses "started" only, while box2 uses "started,continued".

Type vs. On-End

Use type to filter on-collide. Use on-end for ended events rather than including "finished" in type, keeping the two channels cleanly separated.

Source

Set the type attribute on <arashtad-collision> to a comma-separated list of collision phases. 

<arashtad-mesh
    id="box1"
    type="Box"
    size="1"
    position="new BABYLON.Vector3(0, 8, 0)"
    material="green"
>
    <arashtad-physics
        type="BOX"
        mass="1"
        restitution="0.8"
    >
        <arashtad-collision
            type="started"
            on-collide="
                console.log('STARTED', event);
            "
        ></arashtad-collision>
    </arashtad-physics>
</arashtad-mesh>

<arashtad-mesh
    id="box2"
    type="Box"
    size="1"
    position="new BABYLON.Vector3(0, 3, 0)"
    material="orange"
>
    <arashtad-physics
        type="BOX"
        mass="1"
        restitution="0.8"
    >
        <arashtad-collision
            type="started,continued"
            on-collide="
                console.log(event.type, event);
            "
        ></arashtad-collision>
    </arashtad-physics>
</arashtad-mesh>

<arashtad-mesh
    id="ground"
    type="Ground"
    width="10"
    height="10"
    material="brown"
>
    <arashtad-physics
        type="BOX"
        mass="0"
    ></arashtad-physics>
</arashtad-mesh>

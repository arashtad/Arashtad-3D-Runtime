Runtime Model Hierarchy

When a model is imported, Arashtad 3D Runtime creates a TransformNode root for the imported model. The imported model hierarchy remains beneath that runtime root.

Hierarchy
linux-root
└── root
    ├── black
    ├── white
    └── orange
Child Mesh References

The imported meshes can be referenced by their actual Babylon mesh names. In this model those names are black, white, and orange.

Click any visible Linux component in the scene to see which imported mesh received the event.

Nested Mesh References

Mesh references can be placed inside the model element. The runtime resolves the imported mesh and applies the requested properties or events to it.

Black

References the imported black mesh. Picking it updates the status display.

White

References the imported white mesh. Picking it updates the status display.

Orange

References the imported orange mesh. Picking it updates the status display.

Source

The complete runtime markup for the model root example. 

<arashtad-model
    id="linux"
    src="../../../assets/3d/linux.glb"
    position="new BABYLON.Vector3(0, -0.5, 0)"
    scaling="new BABYLON.Vector3(5, 5, 5)"
>

    <arashtad-mesh
        ref="black"
        OnPickTrigger="
            document.getElementById('model-root-status').textContent =
                'Selected mesh: black';
        "
    ></arashtad-mesh>

    <arashtad-mesh
        ref="white"
        OnPickTrigger="
            document.getElementById('model-root-status').textContent =
                'Selected mesh: white';
        "
    ></arashtad-mesh>

    <arashtad-mesh
        ref="orange"
        OnPickTrigger="
            document.getElementById('model-root-status').textContent =
                'Selected mesh: orange';
        "
    ></arashtad-mesh>

</arashtad-model>
